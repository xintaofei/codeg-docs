# 通用

**设置 → 通用** 是一个包罗万象的界面：少量应用行为 —— 新终端打开哪个 shell，以及在 Windows 上窗口如何绘制 —— 之后是四个开关，用来决定 **Codeg 向你的智能体提供哪些额外工具**。应用对它的总结是：*“集中管理默认终端、渲染加速和多智能体委派的偏好设置。”*

本界面共用两种保存方式。**默认终端** 和 **渲染** 在你更改的那一刻就生效（渲染随后会要求重启）。下方四个工具面板则各自带有自己的 **保存** 按钮 —— 在你按下之前，那里的任何设置都不会生效。

## 默认终端 {#default-terminal}

选择当你从终端栏或文件树打开一个新终端标签页时，Codeg 启动的 shell。**默认 shell** 下拉框是通过探测你的机器构建的，因此它列出的是你实际拥有的：

- **系统默认** —— 由你的操作系统提供的任何 shell。下拉框下方的文字会显示它当前解析出的 shell。
- **具名 shell** —— 在 Windows 上是 *PowerShell 7 (pwsh)*、*Windows PowerShell* 和 *Command Prompt (cmd)*；未安装的 shell 仍会出现，并标注为 *未安装*。
- **自定义路径** —— 输入一个绝对路径（或可在 `PATH` 上解析的名称），然后 **保存**。如果该路径在此主机上不存在，Codeg 会警告你，但仍允许你保存。

选择具名选项会立即保存；自定义路径则要等旁边的保存按钮。

这个 shell 所服务的终端，就是[工作区](/zh/guide/workspace)中的那个。

## 渲染 *（仅限 Windows 桌面）* {#rendering-windows-desktop-only}

一个复选框 —— **禁用硬件加速**。如果应用出现黑屏或渲染故障（常见于某些 AMD GPU 或 Intel 集成显卡），就打开它。它会改变底层 webview 的绘制方式，因此 Codeg 会保存该选择，然后要求你 **立即重启** 以使其生效。

本节仅在 **Windows 桌面版本** 上出现 —— 在 macOS、Linux 以及任何浏览器会话中都会隐藏，因为在那些环境里它不起作用。

## 多智能体协作 {#multi-agent-collaboration}

这个开关允许一个活动中的智能体将子任务交给其他智能体 —— 也就是 Codeg 的**委派**功能。界面上这张卡片名为**多智能体协同**，两个标签页：

- **通用** —— **启用委托**（默认关闭；关闭时，`delegate_to_agent` 工具会从智能体的工具目录中隐藏）、**最大委托深度**（1–8，默认 **1** —— 智能体生成智能体的链条可以递归多深），以及 **已完成结果缓存（MB）**（默认 512 —— 在主导会话运行期间，内存中保留多少已完成子智能体的输出；`0` = 无限制）。
- **子智能体配置** —— 按智能体设置的覆盖项（模式和配置），当一次委派调用将该智能体作为工作者生成时应用。这些标签页由实时的智能体注册表构建，因此[自定义智能体](/zh/guide/custom-agents)也会有一个；而各项选项来自对每个智能体的实时探测 —— 你选的正是它将接受的。

按 **保存** 以应用。本面板是控制界面；具体的操作方法 —— 编写委派提示词、观察团队、把工作流转化为技能 —— 见 **[使用多智能体协作](/zh/guide/multi-agent)**。

::: info 目标列表跟随你的启用开关
`delegate_to_agent` 只会公布你实际能启动的智能体，并在每次智能体启动时重新读取：你在**设置 → 智能体**中禁用的内置智能体会从它的目标列表中划掉，已启用的自定义智能体会被加进去，而被禁用的则根本不会被提供。因此关掉一个智能体，不仅是把它从 composer 选择器中隐藏，也把它从主导智能体眼前隐藏了。
:::

## 实时反馈 {#live-feedback}

**启用实时反馈**（默认关闭）让你可以在智能体*工作过程中*向它发送备注和更正。开启后，可以为智能体提供一个工具来检查你在回合中途的反馈，对话在回合运行期间也会显示一个备注输入栏。

有一点值得注意：智能体通常只在你要求时才会去查看反馈 —— 在提示词中加入类似 *“定期检查我的实时反馈”* 之类的话，好让智能体知道要主动拉取它。

## 向用户提问 {#ask-user-question}

**启用向用户提问**（默认开启）让智能体可以暂停并向你抛出一个多选题，以卡片形式呈现在对话输入框上方。智能体会阻塞，直到你回答或跳过。开启它会为智能体添加 `ask_user_question` 工具。

## 获取会话信息 {#get-session-info}

**启用获取会话信息**（默认开启）让智能体可以将你在 composer 中引用的会话 —— 一个形如 `codeg://session/<id>` 的会话徽章 —— 解析为它的标题、智能体、状态、工作区、令牌用量和最近的消息。它是只读的，会为智能体添加 `get_session_info` 工具。

现在这个工具会向智能体讲清那个徽章的*含义*：提及一个会话，就是你在刻意指向它，因此智能体无需被要求就会去查阅，你提及几个会话它就查几次。这与把 `@智能体` 提及当作委派指令是同一个思路。→ [接续另一段会话未竟的工作](/zh/guide/multi-agent#pick-up-where-another-session-left-off)

## 值得了解 {#good-to-know}

- **两种保存方式。** 终端和渲染在更改时即生效；四个工具面板各自需要自己的 **保存** 按钮 —— 而渲染还额外需要一次重启。
- **工具开关在智能体下一次启动时生效。** 这四个开关中的每一个都会“为此开关打开之后启动的智能体”添加或移除一个工具 —— 此刻正处于连接状态的智能体不会在中途获得或失去该能力。但这并不要求是一个全新的对话：任何对话都会在它的智能体下一次启动时采用该改动，包括一个连接已结束、你之后又回到的既有对话。新建一个对话只是最稳妥的方式。
- **这些是 codeg-mcp 工具。** 委派、实时反馈、向用户提问和会话查询都由 [`codeg-mcp` 伴随进程](/zh/reference/architecture)提供；这里的开关决定哪些出现在每个智能体的目录中。
- **渲染仅限 Windows。** 在其他所有环境中，本节干脆不存在。
