# 通用

**设置 → 通用** 是一个包罗万象的界面：少量应用行为 —— 新终端打开哪个 shell、窗口如何绘制、智能体需要你时 Codeg 用什么方式叫你 —— 之后是那些用来决定 **Codeg 向你的智能体提供哪些额外工具** 的开关。

本界面共用两种保存方式。**默认终端**、**禁用硬件加速**、**桌面通知** 和 **提示音** 在你更改的那一刻就生效（渲染随后会要求重启）。下方两个面板 —— **多智能体协作** 和 **会话内工具** —— 各自带有自己的 **保存** 按钮，在你按下之前，两者中的任何设置都不会生效。

## 默认终端 {#default-terminal}

选择当你从终端栏或文件树打开一个新终端标签页时，Codeg 启动的 shell。**默认 shell** 下拉框是通过探测你的机器构建的，因此它列出的是你实际拥有的：

- **系统默认** —— 由你的操作系统提供的任何 shell。下拉框下方的文字会显示它当前解析出的 shell。
- **具名 shell** —— 在 Windows 上是 *PowerShell 7 (pwsh)*、*Windows PowerShell* 和 *Command Prompt (cmd)*；未安装的 shell 仍会出现，并标注为 *未安装*。
- **自定义路径** —— 输入一个绝对路径（或可在 `PATH` 上解析的名称），然后 **保存**。如果该路径在此主机上不存在，Codeg 会警告你，但仍允许你保存。

选择具名选项会立即保存；自定义路径则要等旁边的保存按钮。

这个 shell 所服务的终端，就是[工作区](/zh/guide/workspace)中的那个。而从 **0.25** 起，它不只是那个终端：当一个**智能体**请求 Codeg 执行一整条命令行时，那条命令也走这个 shell。保持在*系统默认*上，则与以前完全一样。

::: warning 非 POSIX 的 shell 可能读不懂智能体写的东西
智能体产出的是 **POSIX 语法**——`&&`、`2>&1`、`$(…)`。你交互时用什么 shell 是你的自由，但把这里指向一个不读 POSIX 的 shell，意味着智能体的命令行可能直接报语法错误，而不是做成任何事。会踩到这一点的是 **fish**、**nushell** 和 **Windows PowerShell 5.1**；PowerShell 7 和 cmd 各有自己的调用约定，已被单独处理。
:::

## 禁用硬件加速 {#disable-hardware-acceleration}

一个开关，以它做的事命名，而不是以它所属的类别命名 —— 把它打开，关掉的是加速。当应用出现黑屏或渲染故障时可以找它：Windows 上某些 AMD GPU 与 Intel 集成显卡，以及 Linux 上的 NVIDIA 闭源驱动。它会改变底层 webview 的绘制方式，因此 Codeg 会保存该选择，然后要求你 **立即重启** 以使其生效 —— 而且从 **0.30.3** 起，把它重新关掉同样会在那次重启后生效，不再被新进程继承下来、看起来像是没关掉。

本节出现在**本机的 Windows 或 Linux 桌面窗口**里，因为那里才有可拧的旋钮：WebView2 与 WebKitGTK 各自暴露了一个应用能在启动时翻转的开关。macOS 的 WKWebView 一个也没有，所以那里干脆不显示这个开关，而不是给一个按了也没用的；浏览器会话同样没有；而**连接到远程工作区**的桌面窗口也会把它隐藏起来，因为它要重绘的 webview 是本机这个，而你正在编辑的设置属于远端主机。

## 桌面通知 {#desktop-notifications}

当智能体需要你时，Codeg 会弹出一条**系统通知** —— 这是与提示音同一个想法的另一半，也正因如此它们紧挨着：一个会离开这个窗口，一个不会。

**它默认是开着的**，和它下面的提示音相反，而这个不对称是刻意的：桌面通知在这个界面出现之前就已经能用，所以那个给它们加上开关的版本，不能同时成为悄悄停止投递它们的版本。提示音则是真正新增的东西，一个安静的安装理应保持安静。所以这里的默认值就是把旧行为写下来 —— 全部打开，只在窗口不在视野里时投递。无论如何本节初始都是折叠的；把总开关打开会同时展开，因为那本来就是一个「想看看它有什么」的请求。

四组控制项：

- **权限** —— 这个浏览器或这台机器到底会不会真的显示通知，明说而不是默认它会。**已允许**、**已阻止**（只有浏览器自己的站点设置能撤销，页面无法再次询问）、**尚未请求**，并附一个**允许通知**按钮；或者**不可用**，意思是页面不在安全上下文里：请通过 HTTPS 或 localhost 访问这台服务器。桌面应用是诚实的那个特例 —— 它通过系统通知中心投递，而系统**不会回报** Codeg 是否被允许，所以它写的是*由系统管理*，并提供**发送测试通知**与**打开系统设置**，而不是给你一个它只能靠猜的状态。
- **投递身份** —— 系统把这些通知归到哪个应用名下。正常情况下是 Codeg；如果 Codeg 自己的标识没能被认领，这一行会点出实际生效的是哪个应用的开关，并说明把 Codeg 装进「应用程序」文件夹就能恢复它自己的身份。
- **何时通知** —— **始终**、**窗口未聚焦时**，或**窗口不可见时**。最后一个是默认值，也是最严格的一个，它就是这项设置存在之前 Codeg 的行为。它同时也是*「我从来收不到通知」*的答案：一个开在第二块显示器上的窗口是**可见的**，所以「不可见时」永远不会为它触发。如果说的是你，就选「未聚焦时」。
- **隐藏通知内容** —— 用一句通用的话替换正文，使智能体的输出永远不会进入通知中心 —— 通知中心会把内容留在应用之外，在你已经关掉那段对话之后依然如此。标题仍会写明文件夹，所以你还是知道该回到哪个窗口。

再往下是逐事件的开关，共六个：**对话完成**、**权限请求**、**智能体提问**、**代理错误**、**后台任务**和**工作任务**。几秒之内同一事件的重复会合并成一条通知。

::: info 事件列表不等于提示音列表
提示音对应的是[聊天频道](/zh/guide/chat-channels)推送的那五个触发点。通知对应的则是这个应用实际会去提醒的事，两者并不相同：它**多了**一个落定的[后台任务](/zh/guide/workspace)，以及一个进入待审或失败的[工作任务](/zh/guide/tasks) —— 这两个应用层的事件在智能体协议里根本没有对应的信封 —— 同时**去掉了***发送消息*，那是你自己敲键盘的回声，没有理由出现在通知中心里。
:::

## 提示音 {#notification-sounds}

默认关闭。打开之后，智能体事件会播放一段短提示音，于是你可以把一个长回合丢在另一个窗口里跑，同时仍然知道它什么时候需要你。

这五个事件与[聊天频道](/zh/guide/chat-channels)推送的完全一致 —— 同样的触发点，不同的出口；频道消息会离开这台机器，提示音不会：

| 事件 | 默认音效 |
| ----- | ------------ |
| **对话完成** | 叮咚 |
| **权限请求** | 警示 |
| **智能体提问** | 清铃 |
| **代理错误** | 下行音 |
| **发送消息** | 静音 |

可选的音效共七种 —— *叮咚、清铃、短音、轻点、警示、下行音*，外加**静音**，用来单独跳过某个事件而不影响其余 —— 每一种都有**试听**按钮。*发送消息*默认静音，因为它是由你自己的动作触发的，在五者中最没有提示价值。

有两项设置作用于全部事件：一个**音量**滑块，以及**仅在窗口未聚焦时播放** —— 你正盯着 Codeg 时保持安静。

和桌面通知一样，本节也是**初始折叠**的 —— 这两节加在一起，从前会把整页占满，让下面的东西都得先翻过去才看得到。

::: info 两者都按设备保存
通知和提示音是本界面上仅有的两个存在你所使用的那个浏览器或应用里、而不是存在 Codeg 数据库里的部分。提醒落在哪里，是你所在那台机器的属性：一个连着同一台服务器的手机浏览器，没有理由因为你的桌面端配置过就开始响 —— 或者震。对提示音来说，它同时还意味着只会在那台设备的**工作区窗口**里播放。
:::

## 多智能体协作 {#multi-agent-collaboration}

这个开关允许一个活动中的智能体将子任务交给其他智能体 —— 也就是 Codeg 的**委派**功能。界面上这张卡片名为**多智能体协同**，两个标签页：

- **通用** —— **启用委托**（默认关闭；关闭时，`delegate_to_agent` 工具会从智能体的工具目录中隐藏）、**最大委托深度**（1–8，默认 **1** —— 智能体生成智能体的链条可以递归多深），以及 **已完成结果缓存（MB）**（默认 512 —— 在主导会话运行期间，内存中保留多少已完成子智能体的输出；`0` = 无限制）。
- **子智能体配置** —— 按智能体设置的覆盖项（模式和配置），当一次委派调用将该智能体作为工作者生成时应用。这些标签页由实时的智能体注册表构建，因此[自定义智能体](/zh/guide/custom-agents)也会有一个；而各项选项来自对每个智能体的实时探测 —— 你选的正是它将接受的。

按 **保存** 以应用。本面板是控制界面；具体的操作方法 —— 编写委派提示词、观察团队、把工作流转化为技能 —— 见 **[使用多智能体协作](/zh/guide/multi-agent)**。

在这里打开的东西，仍可能在别处被收走，因此面板会明说：**启用委托**下方的一条警告会**点名任何按智能体的 [让智能体自己处理文件和命令](/zh/guide/agents#let-the-agent-handle-its-own-files-and-commands) 开关处于打开状态的智能体**，因为那个开关会刻意收走委托工具。这份名单读自后端实际解析出的策略，而不是对该智能体环境变量的二次猜测——因此它与智能体真正会拿到的东西一致。

::: info 目标列表跟随你的启用开关
`delegate_to_agent` 只会公布你实际能启动的智能体，并在每次智能体启动时重新读取：你在**设置 → 智能体**中禁用的内置智能体会从它的目标列表中划掉，已启用的自定义智能体会被加进去，而被禁用的则根本不会被提供。因此关掉一个智能体，不仅是把它从 composer 选择器中隐藏，也把它从主导智能体眼前隐藏了。
:::

## 会话内工具 {#in-conversation-tools}

一张卡片，五个开关，一个 **保存** —— *"codeg 在会话中额外提供给智能体的工具。工具在智能体启动时注入，改动只对之后启动的智能体生效。"*

| 开关 | 默认 | 智能体因此获得什么 |
| ------ | ------- | -------------------- |
| **实时反馈** | 关闭 | 在它*工作过程中*接收你的备注与纠偏 —— 见下文 |
| **向用户提问** | 开启 | 暂停并向你抛出一个多选题，以卡片形式呈现在对话输入框上方。智能体会一直等到你作答或跳过 |
| **获取会话信息** | 开启 | 把你引用的会话 —— 形如 `codeg://session/<id>` 的徽章 —— 解析为它的标题、智能体、状态、工作区、Token 用量和最近的消息。只读 |
| **创建自动化** | 关闭 | 把这次对话保存为按计划运行的[自动化](/zh/guide/automations) |
| **创建待办任务** | 关闭 | 从对话中往[待办看板](/zh/guide/tasks)排一张卡片 |

前三个要么只读、要么只是发问。**后两个会写入应用状态**，这正是它们默认关闭的原因，也是它们除了在智能体启动时之外、还会在工具被调用的那一刻再检查一次的原因：关掉开关能挡住已经在运行的会话继续使用它。

**获取会话信息**会向智能体讲清一个会话徽章的*含义*：提及一个会话，就是你在刻意指向它，因此智能体无需被要求就会去查阅，你提及几个会话它就查几次。这与把 `@智能体` 提及当作委派指令是同一个思路。→ [接续另一段会话未竟的工作](/zh/guide/multi-agent#pick-up-where-another-session-left-off)

### 实时反馈是怎么送到运行中的智能体那里的 {#how-live-feedback-reaches-a-running-agent}

一共有两条通道，你走哪一条取决于智能体。你看到的措辞也随之改变，这是刻意的，因为它们承诺的不是同一件事：

- **直接推进当前回合** —— *插入到当前回合*。如果智能体的适配器支持即时插入，你的备注会进到已经在跑的那份工作里，智能体立刻就能看到。这指的是**适配器 0.65.0 及以上的 Claude Code**，而这个下限是拿**实际在跑的那个适配器**去校验的，而不是 Codeg 本该装上的那个版本 —— 启动时会优先用你 `PATH` 上已有的那一份，所以光凭钉住的版本号证明不了什么。
- **由智能体主动来取** —— *留张便条，等它下次查看*。任何在**启动时**被交给了 `check_user_feedback` 工具的会话都走这条 —— 所以既不包括那些根本收不了 MCP 的智能体，也不包括你在会话中途才打开这个开关的那些。就算拿到了工具，智能体仍然要自己主动去调用，而这类智能体通常只有在你提到时才会去查：请在提示词里加上类似*"定期检查我的实时反馈"*的话。

走拉取通道的备注只是**等着**智能体下一次查看。真正会被改道的，是那种根本没能被记下来的备注 —— 你正在提交时那一轮结束了 —— 它会**改为排队，随下一轮一起发送**，Codeg 会告诉你发生了这件事。附件遵循的是同一个原则的另一面：在推送通道上，带着图片和文件引用的草稿会**整条过去**；在拉取通道上它同样整条不少，只不过是走队列，而不是被剥成一段纯文本。

从 **0.30.3** 起，同样这两条通道也驱动着 composer 的**中途发送** —— 智能体工作时出现的那个分体发送按钮 —— 于是便条不必再绕道 **+** 菜单的对话框。→ [在智能体工作时插话](/zh/guide/workspace#talk-to-an-agent-mid-turn)

## 值得了解 {#good-to-know}

- **两种保存方式。** 终端、渲染、桌面通知和提示音在更改时即生效；委派和会话内工具两个面板各自需要自己的 **保存** —— 而渲染还额外需要一次重启。
- **工具开关在智能体下一次启动时生效。** 每一个开关都会"为此开关打开之后启动的智能体"添加或移除一个工具 —— 此刻正处于连接状态的智能体不会在中途获得或失去该能力。但这并不要求是一个全新的对话：任何对话都会在它的智能体下一次启动时采用该改动，包括一个连接已结束、你之后又回到的既有对话。新建一个对话只是最稳妥的方式。（那两个*创建*类开关是例外，它们在被调用时会再检查一次。）
- **这些是 codeg-mcp 工具。** 委派和全部五个会话内工具都由 [`codeg-mcp` 伴随进程](/zh/reference/architecture)提供；这里的开关决定哪些出现在每个智能体的目录中。不过并非*每一个*伴随工具都由这里管辖——正在执行[待办](/zh/guide/tasks)的智能体还会拿到 `task_progress` 和 `task_complete`，它们由任务引擎注入，而不是由本界面上的任何东西注入。
- **完全不接受 MCP 的智能体一个也拿不到。** 一个把 **MCP 支持** 开关关掉的[自定义智能体](/zh/guide/custom-agents)，连接时根本不会挂载伴随进程，因此本界面上的任何东西都到不了它那里。
- **渲染开关需要 webview 那边真有个旋钮。** 它只出现在**本机的** Windows 或 Linux 桌面窗口里，在 macOS、浏览器，以及连接到远程工作区的桌面窗口里都不存在 —— 每一种情形下，它背后都没有东西可拧。
- **状态栏带着的就是这里这批开关。** 六个全都有：[codeg-mcp 弹层](/zh/guide/multi-agent#the-service-from-the-status-bar)里既有委派，也有全部五个会话内工具。本页开着的时候在那边翻动一个，本页会跟着收敛过去，而不是在下一次保存时把自己那份过期的值送回去。
