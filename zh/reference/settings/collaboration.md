# 协作

**设置 → 协作** 决定一个智能体能够伸到**自己这场对话之外**多远 —— *"智能体之间如何协同，以及它们能在会话中动用 codeg 的哪些工具。"* 两个面板：

- **多智能体协同** —— 一个智能体能不能把子任务交给另一个智能体、链条可以递归多深，以及作为工作者被生成时它带着什么配置。
- **会话内工具** —— 智能体启动时 Codeg 注入的那些工具组：反馈、向用户提问、会话查询、内置浏览器，以及那两个从对话里写入应用状态的工具。

它们在同一页上，是因为两者都由同一个 [`codeg-mcp` 伴随进程](/zh/reference/architecture)在智能体启动时注入，而只看其中一半就做决定，本来也说不通。每个面板**各有自己的保存按钮**，在你按下之前，两者中的任何设置都不会生效。

::: info 0.31.2 新增
这两个面板此前都待在 **设置 → 常规** 的底部，那个界面也因此长到了它名字所暗示长度的两倍。**0.31.2** 把它们挪到了自己的入口，位置在 **技能包** 和 **智能体** 之间。它们做的事没有因为这次搬家而改变。
:::

## 多智能体协作 {#multi-agent-collaboration}

这个开关允许一个活动中的智能体将子任务交给其他智能体 —— 也就是 Codeg 的**委派**功能。界面上这张卡片名为**多智能体协同**，两个标签页：

- **通用** —— **启用委托**（默认关闭；关闭时，`delegate_to_agent` 工具会从智能体的工具目录中隐藏）、**最大委托深度**（1–8，默认 **1** —— 智能体生成智能体的链条可以递归多深），以及 **已完成结果缓存（MB）**（默认 512 —— 在主导会话运行期间，内存中保留多少已完成子智能体的输出；`0` = 无限制）。
- **子智能体配置** —— 按智能体设置的覆盖项（模式和配置），当一次委派调用将该智能体作为工作者生成时应用。这些标签页由实时的智能体注册表构建，因此[自定义智能体](/zh/guide/custom-agents)也会有一个；而各项选项来自对每个智能体的实时探测 —— 你选的正是它将接受的。

按 **保存** 以应用。本面板是控制界面；具体的操作方法 —— 编写委派提示词、观察团队、把工作流转化为技能 —— 见 **[使用多智能体协作](/zh/guide/multi-agent)**。

在这里打开的东西，仍可能在别处被收走，因此面板会明说：**启用委托**下方的一条警告会**点名任何按智能体的 [让智能体自己处理文件和命令](/zh/guide/agents#let-the-agent-handle-its-own-files-and-commands) 开关处于打开状态的智能体**，因为那个开关会刻意收走委托工具。这份名单读自后端实际解析出的策略，而不是对该智能体环境变量的二次猜测——因此它与智能体真正会拿到的东西一致。

::: info 目标列表跟随你的启用开关
`delegate_to_agent` 只会公布你实际能启动的智能体，并在每次智能体启动时重新读取：你在**设置 → 智能体**中禁用的内置智能体会从它的目标列表中划掉，已启用的自定义智能体会被加进去，而被禁用的则根本不会被提供。因此关掉一个智能体，不仅是把它从 composer 选择器中隐藏，也把它从主导智能体眼前隐藏了。
:::

## 会话内工具 {#in-conversation-tools}

一张卡片，七个开关，一个 **保存** —— *"codeg 在会话中额外提供给智能体的工具。工具在智能体启动时注入，改动只对之后启动的智能体生效。"*

| 开关 | 默认 | 智能体因此获得什么 |
| ------ | ------- | -------------------- |
| **实时反馈** | 关闭 | 在它*工作过程中*接收你的备注与纠偏 —— 见下文 |
| **向用户提问** | 开启 | 暂停并向你抛出一个多选题，以卡片形式呈现在对话输入框上方。智能体会一直等到你作答或跳过。自 **0.31.0** 起，问题待答期间卡片可[收起为标题行](/zh/guide/workspace#follow-along-—-the-conversation) |
| **获取会话信息** | 开启 | 把你引用的会话 —— 形如 `codeg://session/<id>` 的徽章 —— 解析为它的标题、智能体、状态、工作区、Token 用量和最近的消息。只读 |
| **读取并操作内置浏览器** | 关闭 | 列出[内置浏览器](/zh/guide/browser#let-an-agent-work-on-the-page)里打开的页面、读取你已共享的那些、在你授予操作权限的那些上动手，以及打开、跳转和关闭标签页 |
| **在内置浏览器中运行代码** | 关闭 | 在你共享为可操作的页面上运行它自己的 JavaScript。需要上面那个开关 —— 而自 **0.31.1** 起，*这个*开关就是那个决定：打开它之后，代码**不再逐段询问**就会运行，除非你把[在页面上运行代码](/zh/reference/settings/browser#running-code-on-a-page)设为*每次都问我* |
| **创建自动化** | 关闭 | 把这次对话保存为按计划运行的[自动化](/zh/guide/automations) |
| **创建待办任务** | 关闭 | 从对话中往[待办看板](/zh/guide/tasks)排一张卡片 |

前三个要么只读、要么只是发问。**另外四个都伸到对话之外** —— 两个伸向你正在看的页面，两个伸向应用状态 —— 这正是它们全部默认关闭的原因，也是它们除了在智能体启动时之外、还会在工具被调用的那一刻再检查一次的原因：关掉开关能挡住已经在运行的会话继续使用它。

那两个浏览器开关只在**桌面应用**里真的把工具交给智能体；浏览器会话里没有原生标签页可供触及，因此这两行在那里是空转的。但要清楚打开第一个开关意味着什么：**默认共享级别**的出厂值是*可读可操作*，因此每个浏览器标签页里的每个页面都会在加载时共享给那个智能体。标签页自己的控件仍可逐页覆盖，选*不共享*则把每一次共享都留给那个控件。→ [让智能体在页面上干活](/zh/guide/browser#let-an-agent-work-on-the-page)

**向用户提问**不再要你点两次弹窗。在每次调用 MCP 工具都要征求你同意的权限模式下——Claude Code 的默认模式——真正的提问卡之前还会先弹出一个把问题以 JSON 原样抛出的「是否运行该工具？」审批。自 **0.31.0** 起，Codeg 会识别自己的提问工具并代为放行，且仅对本轮生效。

**获取会话信息**会向智能体讲清一个会话徽章的*含义*：提及一个会话，就是你在刻意指向它，因此智能体无需被要求就会去查阅，你提及几个会话它就查几次。这与把 `@智能体` 提及当作委派指令是同一个思路。→ [接续另一段会话未竟的工作](/zh/guide/multi-agent#pick-up-where-another-session-left-off)

### 实时反馈是怎么送到运行中的智能体那里的 {#how-live-feedback-reaches-a-running-agent}

一共有两条通道，你走哪一条取决于智能体。你看到的措辞也随之改变，这是刻意的，因为它们承诺的不是同一件事：

- **直接推进当前回合** —— *插入到当前回合*。如果智能体的适配器支持即时插入，你的备注会进到已经在跑的那份工作里，智能体立刻就能看到。这指的是**适配器 0.65.0 及以上的 Claude Code**，而这个下限是拿**实际在跑的那个适配器**去校验的，而不是 Codeg 本该装上的那个版本 —— 启动时会优先用你 `PATH` 上已有的那一份，所以光凭钉住的版本号证明不了什么。
- **由智能体主动来取** —— *留张便条，等它下次查看*。任何在**启动时**被交给了 `check_user_feedback` 工具的会话都走这条 —— 所以既不包括那些根本收不了 MCP 的智能体，也不包括你在会话中途才打开这个开关的那些。就算拿到了工具，智能体仍然要自己主动去调用，而这类智能体通常只有在你提到时才会去查：请在提示词里加上类似*"定期检查我的实时反馈"*的话。

走拉取通道的备注只是**等着**智能体下一次查看。真正会被改道的，是那种根本没能被记下来的备注 —— 你正在提交时那一轮结束了 —— 它会**改为排队，随下一轮一起发送**，Codeg 会告诉你发生了这件事。附件遵循的是同一个原则的另一面：在推送通道上，带着图片和文件引用的草稿会**整条过去**；在拉取通道上它同样整条不少，只不过是走队列，而不是被剥成一段纯文本。

从 **0.30.3** 起，同样这两条通道也驱动着 composer 的**中途发送** —— 智能体工作时出现的那个分体发送按钮 —— 于是便条不必再绕道 **+** 菜单的对话框。→ [在智能体工作时插话](/zh/guide/workspace#talk-to-an-agent-mid-turn)

## 值得了解 {#good-to-know}

- **两个保存按钮，不是一个。** 委派面板和会话内工具卡片各按各的按钮生效。本界面上没有任何东西是你一翻动就生效的。
- **工具开关在智能体下一次启动时生效。** 每一个开关都会"为此开关打开之后启动的智能体"添加或移除一个工具 —— 此刻正处于连接状态的智能体不会在中途获得或失去该能力。但这并不要求是一个全新的对话：任何对话都会在它的智能体下一次启动时采用该改动，包括一个连接已结束、你之后又回到的既有对话。新建一个对话只是最稳妥的方式。（那两个*创建*类开关和那两个*浏览器*开关是例外，它们在被调用时会再检查一次 —— 关掉能挡住已经在运行的会话。）
- **这些是 codeg-mcp 工具。** 委派和全部七个会话内工具都由 [`codeg-mcp` 伴随进程](/zh/reference/architecture)提供；这里的开关决定哪些出现在每个智能体的目录中。不过并非*每一个*伴随工具都由这里管辖——正在执行[待办](/zh/guide/tasks)的智能体还会拿到 `task_progress` 和 `task_complete`，它们由任务引擎注入，而不是由本界面上的任何东西注入。
- **完全不接受 MCP 的智能体一个也拿不到。** 一个把 **MCP 支持** 开关关掉的[自定义智能体](/zh/guide/custom-agents)，连接时根本不会挂载伴随进程，因此本界面上的任何东西都到不了它那里。
- **状态栏带着的就是这里这批开关。** 八个全都有：[codeg-mcp 弹层](/zh/guide/multi-agent#the-service-from-the-status-bar)里既有委派，也有全部七个会话内工具，它的**打开设置**链接落点就是本页。本页开着的时候在那边翻动一个，本页会跟着收敛过去，而不是在下一次保存时把自己那份过期的值送回去。
